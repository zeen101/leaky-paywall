== Installation ==

1. Upload the entire `leaky-paywall` folder to your `/wp-content/plugins/` folder.
2. Go to the `Plugins` page in WordPress and activate the plugin.

== Frequently Asked Questions ==

= How does Leaky Paywall work? =

The Leaky Paywall meter restricts by X number of free articles over a Y time period (days, weeks, months, years). There is a visibility setting on the post edit screen you can use to override the global meter setting, for example making an article always free or always require a subscription.

= What is List Builder? =

List Builder is a prebuilt registration wall and login system modeled after the New York Times. It prompts readers to register with their email to continue reading, helping grow your email list faster than traditional popup newsletter prompts. Registration and login happen in the same seamless flow.

= How does pricing work? =

Leaky Paywall 5.0 is free to install and use. If you add paid subscription levels, the free plan includes a 10% revenue share on new paid subscriptions. You only pay when you make money. Upgrade to a paid plan at any time to reduce or completely remove the revenue share.

= What payment gateways do you support? =

We support Stripe by default and are a Stripe Verified Partner. Apple Pay, Google Pay, and other methods are supported through Stripe. Paid plans unlock hundreds of additional international payment gateways via WooCommerce integration.

= What kind of subscriptions can I create? =

You can create multiple subscription tiers such as free, premium, annual, or VIP. The free plugin supports one-time payments. Recurring payments, trials, and coupons are available on paid plans.

= If I deactivate Leaky Paywall will I lose all my subscriber data? =

You can deactivate Leaky Paywall at any time without losing any subscriber data. All subscribers are stored as WordPress users in your database.

== Changelog ==

= 5.3.8 =
* New: the subscriber page has a "View in Insights" link that opens the subscriber in Leaky Paywall Insights.

= 5.3.7 =
* Fix: payment events from Stripe and PayPal not reaching Insights since 5.3.0.

= 5.3.6 =
* Fix: A Stripe renewal paid from a reader's account credit (for example, after switching from an annual to a monthly plan) now keeps their access, as long as they have no unpaid invoice. Previously these renewals were treated as unpaid and the reader lost access.
* Fix: Level prices entered with a currency symbol (such as "$27") are now saved as plain numbers. Checkout previously showed "An unexpected error occurred" for these levels. A price that still isn't a number now stops checkout with a clear message and is recorded in the debug log.
* Fix: Prices with a partial decimal now display with the configured number of decimal places ($49.50 instead of $49.5).
* Fix: A Stripe trial that is set to cancel now shows as pending cancel when the subscriber is synced, instead of as an active trial.
* Fix: When both card and PayPal are offered, card is now selected by default.
* Improvement: The payment method selector on the registration form has a new tile design, and is hidden when only one payment method is offered. Developers can style it with the --lp-payment-method-* CSS variables and control it with the leaky_paywall_show_payment_method_selector filter.
* Improvement: The Stripe payment form can be styled with the new leaky_paywall_stripe_elements_appearance and leaky_paywall_stripe_elements_fonts filters.
* Improvement: List Builder's subheading and terms text now allow line breaks, bold, italics and links.

= 5.3.5 =
* New: Leaky Paywall can now answer questions from AI assistants connected to your site through the WordPress Abilities API (WordPress 6.9 or later), such as "why can't this reader see paid content?" and "what subscription levels do we sell?". Read-only and admin-only. Turn it on under Settings > General > AI Assistants (off by default).
* Fix: When a reader's browser blocks the Stripe payment form (cookie settings, a browser extension or a work network), the registration form now explains the problem instead of leaving a Next button that does nothing, and the attempt is recorded in the debug log with the likely cause.
* Fix: Reading subscribers through the Leaky Paywall REST API no longer changes their status. A subscriber whose expiration date has passed is reported with has_access false and keeps their stored status until their next visit or the daily expiration check.
* Improvement: Removed an unused Insights reports request handler and its unused scripts.

= 5.3.4 =
* Fix: Stripe signups no longer get stuck on "Processing" after clicking Next when the Billing Address option is turned on.
* Fix: A partial refund in Stripe no longer removes a subscriber's access. Only a full refund ends access, and the refund is still recorded.
* Fix: A delayed trial with a setup fee now stays on trial until it converts, instead of showing as active once the fee is paid.
* Fix: Row actions, including Send Receipt, show again on the Transactions list.
* Improvement: The registration Next button now reads "Continue to Payment". Developers can change it with the leaky_paywall_registration_next_text filter.
* Improvement: Logged-in readers no longer see an empty Account Details heading on the registration form.
* Improvement: Quick Edit and Trash are removed from individual transaction rows, since transactions are financial records. Trash is still available as a bulk action.
* Improvement: List Builder now enforces its minimum password length on signup. Developers can change it with the lp_list_builder_min_password_length filter.
* New: Developers can let a logged-in reader buying another level start a separate Stripe subscription instead of switching their current one, using the leaky_paywall_stripe_switch_existing_subscription filter.

For older changelog entries, please see the [changelog.txt file](https://plugins.svn.wordpress.org/leaky-paywall/trunk/changelog.txt) delivered with the plugin.
